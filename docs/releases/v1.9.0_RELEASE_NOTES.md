## Phase 2 Sub-Phase Summary

### Phase 2.1 — Branch Configuration & Settings Versioning (ADR-001 + ADR-002)

- **ADR-001** — Branch Configuration Inheritance & Overrides. Establishes tenant defaults → brand defaults → branch overrides inheritance chain. Already shipped via migrations `20260805190000` + `20260805200000` (creates `configuration_schemas`, `configuration_versions`, `configuration_change_log`). This release authors the standalone ADR markdown.
- **ADR-002** — Settings Versioning, Activation & Rollback Model. Each settings change creates a new row in `configuration_versions` with status `draft` → `active` → `archived`; exactly one `active` version per `(schema_id, scope_id)` enforced by partial unique index. Rollback is a state transition (not DELETE). Already shipped via migrations `20260806150140` + `20260806170223`.
- **PR:** #228 (docs-only, squash `9fc446f`).

### Phase 2.2 — WhatsApp Foundation (ADR-003 + ADR-004)

- **ADR-003** — Provider-Secret Boundary Architecture. Cross-cutting security ADR: secrets live ONLY in server-side env vars; DB stores reference keys (`config_ref`).
- **ADR-004** — WhatsApp Conversation Ownership & Routing. Branch ownership, agent RLS scoping with super-admin cross-branch visibility, provisional customer identity, conversation state machine (`open` → `in_progress` → `resolved`/`escalated` → `closed`), message immutability, 24-month PII retention, idempotent webhook upsert via `wamid` UNIQUE.
- **Migrations applied to Production:** `20260816000000` (ADR-003), `20260816000100` (ADR-004), `20260816000200` (FU-1 immutability fix), `20260816000250` (FU-2 `provider_next_attempt_at` column + partial index), `20260816000300` (FU-3 `whatsapp_anonymize_pii()` RPC).
- **Backend modules:** `services/whatsapp/{mock-client,cloud-api-client,adapter-factory,inbound-worker,outbox-worker,admin-service,pii-anonymization}.ts`, `modules/webhooks/whatsapp.ts`, `modules/admin/whatsapp.ts` (11 endpoints), `app.ts` raw-body capture for HMAC.
- **Frontend:** honest-gap language flipped to "WhatsApp inbox is live"; live conversation workspace + composer + KPIs. 11 typed admin API client functions added.
- **PRs:** #218 (foundation), #219 (inbound worker), #220 (outbox + admin routes), #221 (frontend + PII job), #222 (FU-2 hotfix — partial index cannot use `now()`).

### Phase 2.3 — CRM (ADR-005 + ADR-006)

- **ADR-005** — Canonical Customer Identity Strategy. `customers.id` is canonical; `customer_identities` table maps multiple identity types (phone, email, whatsapp) to one customer. `normalize_phone_e164()` ensures Pakistani numbers stored consistently. `resolve_customer_by_identity()` RPC. `auto_create_customer_identities()` INSERT trigger backfills from existing `customers.phone`/`email`.
- **ADR-006** — Customer Account Merge & Reversal Process. `merge_customers_atomic()` RPC transfers FKs from source → target in single transaction; `reverse_customer_merge()` within 30-day window. `customer_merge_log` append-only via trigger.
- **Migration applied to Production:** `20260818000000` (3 tables, 6 functions, extended `customers.status` CHECK with `'merged'`, `customers.merged_into_id` column, backfill DO block).
- **Backend modules:** `services/customers/{identity,merge}-service.ts`, `modules/admin/customers.ts` (8 endpoints, merge+reverse super-admin only).
- **Tests:** 36 new tests in `customer-identity-merge-service.test.ts`.
- **PR:** #225 (squash `59bf158`).

### Phase 2.4 — Delivery & Rider Completion (ADR-008 + ADR-009 + ADR-010)

- **ADR-008** — Rider Location Retention & Privacy Policy. `rider_locations` table with 24-hour retention. `purge_expired_rider_locations()` TTL function (idempotent).
- **ADR-009** — Proof of Delivery (POD) Data Format & Storage. `delivery_pod` table (UNIQUE on `delivery_id`): signature (base64 PNG), photo URL (Supabase Storage bucket `delivery-pod`), recipient name, GPS, timestamp. Immutability trigger. Extended ADR-007 transition validator to require POD before `delivered`.
- **ADR-010** — Cash on Delivery (COD) Financial Ownership. `cod_collections` table (UNIQUE on `delivery_id`). Reconciliation state machine: `pending` → `reconciled`/`shortage`/`overage`. `post_cod_collection_journal()` trigger fires `create_journal_entry_atomic` + `finance_postings` link (idempotent).
- **Migration applied to Production:** `20260817000000` (3 tables, 5 functions, `delivery.access` permission).
- **Backend modules:** `services/deliveries/{rider-location,rider-location-ttl,pod,cod}-service.ts`, `modules/admin/delivery-rider.ts` (10 endpoints).
- **Tests:** 51 new tests across 3 files.
- **PR:** #224 (squash `2eaaa9b`).

### Phase 2.5 — Domain Event Audit (ADR-012)

- **ADR-012** — Domain Event & Shared Audit Architecture. Centralized append-only `domain_events` table for cross-domain query projection. Each event has `event_type` (regex-validated `<domain>.<verb>`), `domain` enum, `entity_id`, `branch_id`, `actor_user_id`, `actor_role`, `metadata` JSONB, `correlation_id` (for tracing across domains), `occurred_at`. `emit_domain_event()` helper RPC. AFTER INSERT triggers on existing audit tables mirror events into `domain_events`:
  - `delivery_state_transitions` → `delivery.transitioned`
  - `customer_merge_log` → `customer.merged` (and `customer.merge_reversed` on UPDATE of `reversed_at`)
  - `whatsapp_conversation_events` → `whatsapp.<event_type>` (conditional)
  - `order_status_logs` → `order.transitioned` (conditional)
- **Migration applied to Production:** `20260819000000` (1 table, 6 indexes + GIN on `metadata`, 6 functions, `audit.read` permission).
- **Backend modules:** `services/audit/domain-event-service.ts`, `modules/admin/audit.ts` (4 endpoints).
- **FU-1 hotfix:** nested `$$` blocks cause syntax error — fixed using distinct delimiters: outer `do $_$ ... $_$` and inner `as $func$ ... $func$`.
- **Tests:** 17 new tests in `domain-event-service.test.ts`.
- **PR:** #226 (squash `9af1d31`).

### Phase 2.6 — AI Governance (ADR-013 + ADR-014 + ADR-015)

- **ADR-013** — AI Provider Boundary & Data Governance. `ai_provider_configs` table (non-secret metadata only — keys in env vars per ADR-003). `ai_call_logs` table records per-call audit (actor, provider, model, `prompt_sha256` hash only — raw prompts NEVER stored, tokens, latency, cost, success). PII redaction utility `services/ai/pii-redaction.ts` redacts E.164 phones, Pakistani mobiles, emails, credit cards, CNICs before hashing.
- **ADR-014** — AI Human-Approval Gate Architecture. `ai_action_approvals` table (renamed from `ai_approvals` in FU-1 to avoid conflict with existing Phase 4 foundation table). State machine: `pending` → `approved` → `executed`; `pending` → `rejected`; `pending` → `expired` after 7 days. CHECK constraint on `action_type` (allowlist of 9 permitted action types). `ai.approve` permission granted to super-admin + branch-manager only.
- **ADR-015** — AI Prompt & Data Retention Policy. `ai_prompt_logs` table stores hashed metadata only; UNIQUE on `prompt_sha256`; `occurrence_count`, `avg_latency_ms`, `avg_cost_usd` for trend analytics. `upsert_ai_prompt_log()` RPC increments count + rolling averages. Raw prompts NEVER stored in database (only SHA-256 hash of redacted prompt).
- **Migration applied to Production:** `20260820000000` (4 tables, 1 function, `ai.use` + `ai.approve` permissions).
- **Backend modules:** `services/ai/{pii-redaction,approval,prompt-log}-service.ts`, `modules/admin/ai-governance.ts` (7 endpoints).
- **FU-1 hotfix:** existing migration `20260730120000_ai_platform_foundation.sql` already creates `public.ai_approvals` (Phase 4 foundation, simpler schema with `task_id` FK). Fix: rename the new ADR-014 table to `ai_action_approvals`.
- **Tests:** 33 new tests in `ai-services.test.ts`.
- **PR:** #227 (squash `a710def`).

## Operational Notes

### Default disabled; opt-in workers

- **Default `TELEPIZZA_WHATSAPP_MODE=disabled`** — no behavior change for existing deployments. Operators can opt in by setting `TELEPIZZA_WHATSAPP_MODE=mock|sandbox|live` + the 5 `WHATSAPP_*` env vars.
- **Workers are opt-in** in Production:
  - Set `TELEPIZZA_WHATSAPP_WORKER=1` to enable inbound + outbound WhatsApp workers.
  - Set `TELEPIZZA_RIDER_LOCATION_TTL_JOB=1` to enable the hourly rider-location TTL purge.
  - Set `TELEPIZZA_WHATSAPP_PII_JOB=1` to enable the 24-month PII anonymization job.

### COD reconciliation requires GL setup

Each branch needs `chart_of_accounts` rows with `account_code='CASH'` (ASSET) and `account_code='ACCOUNTS_RECEIVABLE'` (ASSET) for `post_cod_collection_journal()` to produce GL postings.

### POD storage bucket

Configure Supabase Storage bucket `delivery-pod` on the Supabase dashboard:
- Write: authenticated riders.
- Read: branch staff + the order's customer.

### AI provider setup

Configure `ai_provider_configs` rows for each AI provider (OpenAI, Anthropic, etc.). Set API keys in env vars (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, etc.) per ADR-003 — never in the database.
