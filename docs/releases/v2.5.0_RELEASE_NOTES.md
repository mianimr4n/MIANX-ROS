## What's New

### ADR-033 — Inventory Stock Master, Movement Ledger & Atomic Adjustment Contract

Formally accepts the as-built inventory stock + movement ledger +
atomic adjustment surface:

- **Branch-scoped stock master:** `inventory_items` table with
  `(branch_id, sku)` UNIQUE constraint, 3-state status
  (active/inactive/discontinued), `current_stock` (numeric 14,3) with
  CHECK ≥ 0, `minimum_stock` + `reorder_level` advisory thresholds,
  `cost_price` last-known cost.
- **Immutable movement ledger:** `stock_movements` append-only table
  with 8 movement types (receipt, adjustment, transfer_in,
  transfer_out, waste, sale_consumption, purchase, sale). API-layer
  immutability enforcement (no DB-level trigger — DEFERRED).
- **Atomic adjustment RPC:** `adjust_inventory_stock_atomic`
  SECURITY DEFINER function performs INSERT movement + UPDATE stock in
  a single transaction. 4 invariants: QUANTITY_DELTA_INVALID,
  INVENTORY_ITEM_NOT_FOUND, INSUFFICIENT_STOCK (cannot drive
  `current_stock < 0`), MOVEMENT_TYPE_INVALID.
- **RLS:** `current_user_has_branch_access(branch_id)` for SELECT,
  service_role for write. Same pattern as ADR-019/023/027.
- **Permission seed:** `inventory.manage` granted to super-admin +
  branch-manager.
- **Deferred:** low-stock alerts, dedicated `inventory_transfers`
  table, batch/lot tracking, cost history, DB-level immutability
  trigger, units master table, multi-warehouse, `sale` movement
  wiring, stock count workflow.

### ADR-034 — Recipe/BOM & COGS Costing Contract

Formally accepts the as-built recipe + BOM + COGS surface:

- **Versioned recipes:** `inventory_recipes` table with
  `(branch_id, menu_item_id, version)` UNIQUE + partial UNIQUE index
  `uq_inventory_recipes_one_active` enforcing one-active-per-menu_item.
  3-state status (draft/active/inactive) + `yield_factor` +
  `activated_at`/`deactivated_at` timestamps.
- **Recipe lines:** `inventory_recipe_lines` with
  `(recipe_id, inventory_item_id)` UNIQUE, `quantity` + `unit` +
  `waste_factor` (multiplier for trim/spill loss) + `sort_order`.
- **Modifier effects:** `inventory_recipe_modifier_effects` table
  documents per-modifier ingredient deltas (add/remove). **DEFERRED
  for consume path** — kitchen RPC reads base recipe lines only until
  modifier consume is certified.
- **Consumption events:** `inventory_consumption_events` idempotent
  via `UNIQUE(idempotency_key)` + reversible via `reversed_event_id`
  self-FK. `event_type ∈ {consume, reverse}`,
  `status ∈ {posted, reversed, noop}`. Per-ingredient breakdown in
  `inventory_consumption_event_lines` with FK to `stock_movements`.
- **COGS events:** `inventory_cogs_events` records cost-of-goods-sold
  per consumption event. `cost_source` CHECK ∈ {`last_known`,
  `weighted_average`, `fifo`, `manual`} — only `last_known` wired today;
  others forward-compatible.
- **Stock exceptions:** `inventory_stock_exceptions` for variance
  tracking (insufficient_stock, negative_stock, missing_recipe,
  unit_conversion_failed).
- **Cost-availability honesty model:** 4-value `CostAvailability`
  type (LIVE / DERIVED / UNAVAILABLE / DEFERRED) surfaced as colored
  badges in `InventoryInsights.tsx`.
- **API:** 8 recipe routes (list, missing, get, create, update,
  activate, deactivate, duplicate).
- **Deferred:** modifier-effect consume certification, COGS GL
  posting, weighted-average/FIFO costing, cost history, recipe
  versioning rollback, soft-fail mode, yield factor enforcement,
  recipe import/export.

### ADR-035 — Procurement, Suppliers & GRN Contract

Formally accepts the as-built procurement + supplier portal surface:

- **Supplier master:** `suppliers` branch-scoped with `status`
  (active/inactive) + `approval_status` (pending/approved/suspended)
  split. Extended columns: `tax_id`, `business_registration`,
  `payment_terms`, `supplied_categories` (text[]), `notes`.
- **Purchase orders:** `purchase_orders` 8-state machine
  (draft → submitted → approved → ordered → partially_received →
  received | cancelled | rejected). Explicit approval gate via
  `POST /:id/approve` with body `{decision, notes}`. UNIQUE
  `(branch_id, po_number)`.
- **Purchase requisitions:** 6-state machine
  (draft → submitted → approved → converted | rejected | cancelled).
  Optional pre-PO internal request surface.
- **Goods Receiving Notes (GRN):** 3-state machine
  (draft → posted | cancelled). `goods_receiving_lines` with optional
  `inventory_item_id` mapping. `posted` transition is irreversible.
- **Atomic GRN stock posting:** `create_goods_receiving_with_stock_atomic`
  SECURITY DEFINER RPC creates GRN + lines + posts stock via
  `adjust_inventory_stock_atomic` (movement_type=`purchase`) +
  updates parent PO status in a single transaction.
- **Supplier invoices:** `supplier_invoices` with 3-way match
  foundation (`match_status` + `variance_amount` + `matched_grn_id`).
  6-state status (draft/pending_approval/approved/paid/disputed/
  cancelled). 4-state match (unmatched/matched/variance/
  exception_approved).
- **Supplier payments:** `supplier_payments` with
  `record_supplier_payment_atomic` SECURITY DEFINER RPC (records
  payment + updates invoice status + posts to GL via ADR-011).
- **Supplier portal:** 20 routes under `/api/v1/supplier-portal/*`
  for supplier-side PO acknowledgment, accept/reject, amendment
  requests, delivery date proposals, document upload (URL + base64),
  performance KPIs, profile. `supplier` role + `supplier.portal`
  permission seeded. Idempotent responses via
  `UNIQUE(idempotency_key)`.
- **Deferred:** automated 3-way match, DB-level PO state-machine
  trigger, negative-quantity GRN lines (returns), multi-branch PO
  consolidation, supplier SSO, supplier-side invoice submission,
  procurement-to-GL automation, supplier performance scoring,
  multi-level approval workflow, RFQ flow, supplier PO ack SLA,
  contract management, inventory reservation.
