## What's New

### ADR-036 — Branch GL, P&L, Balance Sheet & Cash Flow Contract

Formally accepts the as-built branch General Ledger + financial
statement surface:

- **Branch-scoped Chart of Accounts:** `chart_of_accounts` table with
  5 account types (ASSET, LIABILITY, EQUITY, REVENUE, EXPENSE), UNIQUE
  `(branch_id, account_code)`, optional `parent_account_id` for
  hierarchical reporting, `is_active` flag.
- **Double-entry journal:** `journal_entries` table with 3-state status
  (draft → posted | voided) + `reference_type`/`reference_id` for
  source linking (orders, supplier_invoices, expense_claims, COD
  collections, etc.) + `reversed_by_journal_id` + `reverses_journal_id`
  self-FK for symmetric reversal chains.
- **Balanced journal lines:** `journal_entry_lines` with CHECK
  constraint requiring exactly one of `debit`/`credit` to be positive
  per line — guarantees double-entry balance.
- **Atomic journal creation:** `create_journal_entry_atomic` SECURITY
  DEFINER RPC validates (a) sum of debits = sum of credits, (b) ≥2
  lines, (c) all accounts belong to the same branch as the journal
  entry. `reverse_journal_entry_atomic` RPC posts an equal-and-opposite
  posted entry and marks the original `voided` — both protected by
  ADR-011 immutability triggers.
- **Period control:** `finance_periods` 3-state (open / soft_closed /
  closed) with UNIQUE `(branch_id, period_start, period_end)`.
  `finance_assert_period_allows_posting` SECURITY DEFINER RPC gates
  every controlled GL posting service — closed periods block posting.
- **Account mappings:** `finance_account_mappings` (purpose → account_id
  per branch; UNIQUE branch+purpose) with 20 canonical purposes
  (cash_on_hand, cash_over_short, ap_control, ar_control,
  bank_clearing, expense_default, sales_revenue, sales_discounts,
  output_tax, refunds, inventory_asset, cogs, cash_flow_operating,
  cash_flow_investing, cash_flow_financing, salary_expense,
  allowance_expense, payroll_payable, payroll_tax_payable,
  payroll_deduction_payable) plus `expense_category:*` prefix for
  expense-category-specific postings.
- **Cash accounts + register entries:** `finance_cash_accounts` (kind
  cash/bank, UNIQUE branch+name, opening_balance) +
  `finance_cash_register_entries` (3-type deposit/withdrawal/transfer
  with reconciliation_status).
- **Exception queue:** `finance_exceptions` 3-state (open/resolved/
  ignored) captures controlled-GL-posting failures (missing mapping,
  closed period, etc.) for operator follow-up — never silently drops.
- **Idempotent posting ledger:** `finance_postings` UNIQUE
  `(source_module, source_id)` ensures one-successful-journal-per-source
  even across replays — the foundation for all GL auto-posting services.
- **Financial statements:** `finance_trial_balance` (dynamic, posted
  only, as-of date), `finance_profit_loss` (Revenue credit−debit;
  Expense debit−credit; netIncome), `finance_balance_sheet`
  (assets−liabilities−equity+current earnings, dynamic from posted
  journals), `finance_cash_flow_indirect` (operating+investing+
  financing from account mappings; unclassified movements returned
  explicitly, never silent).
- **ADR-011 immutability:** `enforce_journal_entry_immutability` +
  `enforce_journal_entry_line_immutability` BEFORE UPDATE/DELETE
  triggers block mutation of posted entries except the explicit
  `posted → voided` transition + linkage column updates. Supports
  `app.bypass_immutability=on` for trusted SECURITY DEFINER RPCs.
- **Deferred:** per-branch pricing (ADR-020), automated GL posting
  from kitchen/PO/invoice (manual `/finance/{sales,ap,cogs}/post`
  endpoints exist), multi-currency consolidation (PKR-only),
  inter-branch transfers, fiscal-year close automation, bank
  reconciliation (statement import + matching), fixed-asset
  depreciation.

### ADR-037 — Cash Reconciliation, Z-Report & COD Financial Ownership Contract

Formally accepts the as-built cash reconciliation + Z-report + payments
+ COD financial ownership surface:

- **Z-Report:** `pos_z_report_events` append-only audit table with
  branch_id, business_date, total_orders, total_cash_sales,
  expected_cash, payload jsonb, timezone default 'Asia/Karachi'.
  `PosZReportService.getReport` computes cash-drawer expectation from
  `payments` (method=cash, status=paid, created_at ≥ dayStart Karachi);
  `confirmClose` inserts the audit row.
- **Cash reconciliations:** `cash_reconciliations` 6-state
  (draft → submitted → approved → posted | rejected | voided) with
  opening_float, cash_sales, cash_refunds, cash_drops,
  paid_out_expenses, other_inflows, other_outflows, server-computed
  expected_cash + variance, counted_cash, posting_status 5-state
  (pending/posted/blocked/deferred/voided), journal_entry_id FK,
  z_report_event_id FK, idempotency_key UNIQUE. UNIQUE per
  branch+date+register (WHERE not voided).
- **Immutable totals RPC:** `compute_cash_reconciliation_totals`
  IMMUTABLE function — server-side recomputation of expected_cash +
  variance from raw inputs. Prevents client-side tampering.
- **COD reconciliation:** `cod_collections` 4-state reconciliation
  (pending → reconciled | shortage | overage) with UNIQUE on
  delivery_id, reconciled_amount/at/by, journal_entry_id FK, metadata
  jsonb. `post_cod_collection_journal` SECURITY DEFINER trigger
  function fires on reconciliation_status → reconciled (ADR-010),
  looks up CASH + ACCOUNTS_RECEIVABLE CoA accounts (graceful fallback
  if accounts not configured), idempotent via `finance_postings` UNIQUE
  `source_module='cod_collection'`. Attached via
  `trg_cod_collection_post_journal` AFTER UPDATE trigger.
- **Payments:** `payments` table 8-state status (pending/authorized/
  completed/paid/failed/voided/partially_refunded/refunded), 4 payment
  methods (cash/card_terminal/bank_manual/complimentary), cash_tendered
  + cash_change, idempotency_key UNIQUE, `chk_payments_order_or_bill`
  CHECK (order_id OR restaurant_bill_id required). Extended with
  branch_id, dining_session_id, restaurant_bill_id, received_by,
  terminal_device_ref, completed_at, failed_at, refunded_at, voided_at,
  failure_reason, audit_metadata.
- **Bill splits:** `bill_splits` (4 strategies: equal/even/items/
  custom) + `bill_split_allocations` per-tender allocation rows.
- **Reservation deposits:** `reservation_deposits` 7-state lifecycle
  (paid → waived | forfeited | refunded | applied | voided | expired)
  with payment_method, paid_at, waived_at, forfeited_at, refunded_at,
  applied_at timestamps.
- **Branch payment methods:** `branch_payment_methods` per-branch
  enabled-methods config + verification fields + `branch_payment_method_events`
  audit table. RLS via `current_user_has_branch_access`.
- **Atomic settlement RPCs:** `settle_bill_payment_atomic` (atomic
  payment + bill balance update + idempotency check),
  `close_dining_session_atomic` (atomic session close + bill
  finalization).
- **Permissions seeded:** `payment.read`, `payment.manage` (super-admin
  + branch-manager + cashier + customer-support), `payment.settle`,
  `payment.void`, `deposit.manage`.
- **Deferred:** `pos_sessions` table (POS-BILLING-FOUNDATION §2),
  online card gateway (Stripe/Braintree), multi-tender `payment_splits`
  table (multi-tender handled via multiple payments rows against same
  bill), bank deposit slip generation, multi-timezone (Asia/Karachi
  only).

### ADR-038 — Tax, AR, AP, COGS & Expense Posting Contract

Formally accepts the as-built tax + AR + AP + COGS + expense posting
surface:

- **Tax definitions:** `tax_definitions` table with branch_id optional,
  UNIQUE (branch_id, tax_code), rate numeric 0-1, tax_basis
  (exclusive/inclusive), classification (input/output),
  effective_from/effective_to, payable_account_id/receivable_account_id
  FKs, is_active defaults false (no hardcoded jurisdiction rates —
  operator must seed PK GST/SST per branch via FU-19).
- **Pure tax helpers:** `services/finance/tax-calc.ts` —
  `roundMoney` (half-up 2dp), `isTaxEffectiveOn`,
  `calculateLineTax` (exclusive: subtotal×rate; inclusive:
  subtotal−subtotal/(1+rate)), `calculateInvoiceTaxTotals` (applies
  discount before tax).
- **AR surface:** `customer_invoices` 7-state (DRAFT/ISSUED/
  PARTIALLY_PAID/PAID/OVERDUE/VOID/CREDITED) with UNIQUE
  (branch_id, invoice_number), source_order_id FK; `customer_invoice_lines`;
  `customer_receipts` 4-state payment_method with idempotency_key UNIQUE
  + unapplied_amount; `customer_receipt_allocations` UNIQUE
  (receipt_id, invoice_id); `customer_credit_notes` 3-state
  (DRAFT/ISSUED/VOID) with UNIQUE (branch_id, credit_number).
- **AP surface:** `supplier_invoices` 3-way match foundation
  (match_status + variance_amount + matched_grn_id) with status
  pending/paid/partially_paid + due_date + exception_approved_at/by +
  exception_reason; `supplier_payments` 4-state payment_method
  (cash/bank_transfer/cheque/other) with idempotency_key UNIQUE.
- **Atomic AP payment:** `record_supplier_payment_atomic` SECURITY
  DEFINER RPC — two overloads (7-arg legacy + 8-arg with idempotency).
  Validates branch/supplier match, 3-way match discrepancy block,
  overage block, idempotent replay, status roll pending →
  partially_paid → paid.
- **Expense claims:** `expense_claims` 6-state (draft/submitted/
  approved/rejected/paid/voided) with category, amount, currency
  default 'PKR', payment_method 5-state, payee, receipt_ref,
  journal_entry_id FK, posting_status 5-state, source_context,
  idempotency_key UNIQUE, UNIQUE (branch_id, expense_number).
  `expense_claim_events` audit.
- **COGS events:** `inventory_cogs_events` with cost_source 4-state
  (last_purchase_cost_price/unavailable/weighted_average/fifo),
  status 4-state (pending/posted/deferred/skipped), amount,
  idempotency_key UNIQUE. `inventory_consumption_events` idempotent +
  reversible via `reversed_event_id` self-FK.
- **Controlled GL posting services:** `postSalesFromOrder` (debit
  AR/cash, credit sales_revenue/output_tax/sales_discounts),
  `postSupplierInvoice` (debit AP/expenses, credit bank_clearing),
  `postCogsEvent` (debit cogs, credit inventory_asset),
  `postPayrollAccrual` (debit salary/allowance expense, credit
  payroll_payable/tax_payable/deduction_payable),
  `postPayrollSettlement` (debit payroll_payable, credit cash/bank).
  All gated on `requireMapping` (account mapping must exist) +
  `assertPeriodAllows` (period must not be closed) + `recordException`
  (finance_exceptions queue) — never silently fails.
- **Deferred:** seeded jurisdiction rates, automated COGS GL posting
  from kitchen consume (manual `/finance/cogs/events/:id/post` exists),
  weighted-average/FIFO costing (last_purchase_cost_price only),
  `inventory_cost_history` table, `sale` movement type wiring for
  finished-goods, automated procurement-to-GL automation (manual
  `/finance/ap/invoices/:id/post` exists), automated 3-way match
  (DB-level trigger), supplier-side invoice submission, partial-cancel
  of order line items (ADR-018 negative consequence), dedicated
  `refunds` table (currently `payments.refunded_at` +
  `customer_credit_notes`), partial-refund API (only full void
  currently), discounts master table for non-coupon discounts.
