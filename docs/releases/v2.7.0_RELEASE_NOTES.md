## Headline

**Phase 12 — Customer and Staff Apps — is FEATURE-COMPLETE and Production-verified.**

This release ships **3 new ADRs** formally accepting the as-built
customer-facing and staff-facing application surface: ADR-039
(Customer Mobile & Franchise Portal Contract), ADR-040 (Rider Mobile
App & Delivery Dashboard Contract), and ADR-041 (Staff App & Support
Panel Contract). All 41 ADRs (ADR-001 through ADR-041) are now
Accepted v1.0 with standalone ADR markdown files under `docs/13-adr/`.

Phase 12 is a **closeout phase**: the underlying code has been live in
Production across multiple prior waves — v1.2.0 (Phase 1 customer
website), v1.6.0/v1.10.0 (Phase 2/3 customer auth + OTP), v1.7.0
(Phase 4 orders + tracking), v2.1.0 (Phase 6 admin dashboard +
analytics + CRM), v2.2.0 (Phase 7 POS), v2.3.0 (Phase 8 KDS),
v2.4.0 (Phase 9 rider endpoints + delivery dashboard), v2.5.0
(Phase 10 inventory), and v2.6.0 (Phase 11 finance). This release
adds no new migrations and no new code — only formal ADR elevation
+ verification script + closeout documentation. The Production DB
tip remains `20260821000000` (same as Phase 5/6/7/8/9/10/11
closeouts).

## What's New

### ADR-039 — Customer Mobile & Franchise Portal Contract

Formally accepts the as-built customer-facing + franchise portal
surface:

- **Web-first PWA:** `apps/website` React + Vite single-page app is
  the only customer app — NO native iOS/Android app, NO React Native
  /Expo codebase. PWA manifest (`site.webmanifest`) exists for
  "Add to Home Screen" installability.
- **Customer auth:** ADR-017 phone-first OTP via `/auth/otp/send` +
  `/auth/otp/verify` + `/auth/session`; `customer` role with zero
  admin permissions enforced via `CUSTOMER_FORBIDDEN_PERMISSIONS`
  set in `principal.ts`.
- **Order placement:** Guest + authenticated checkout via
  `POST /api/v1/orders` with Idempotency-Key + server-side quote via
  `POST /api/v1/orders/quote` (ADR-018). `TrackOrder.tsx` (316 lines)
  polls `GET /api/v1/orders/:id` for status + delivery state.
- **Customer account:** `MyTelepizza.tsx` (2,303 lines) consolidates
  loyalty wallet + order history + favorites + addresses + saved
  payment methods into one surface.
- **Loyalty wallet:** ADR-021 points + rewards + coupons; full
  integration with `loyalty_point_balances` + `loyalty_point_ledger`
  tables.
- **Franchise portal:** `organization_owner` role (Identity 01
  migration) scoped to exactly one `organization_id`.
  `AnalyticsService.getOwnerWorkspace` composes 25 analytics
  modules into one payload including `branch_comparison` cross-branch
  KPI matrix. Mounted at `GET /api/v1/admin/reports/owner-workspace`.
  `AdminBranchManager.tsx` (689 lines) provides multi-branch roster
  + per-branch settings + readiness + P&L.
- **Customer notifications:** WhatsApp (ADR-003/004) as primary
  channel — order confirmation, status updates, delivery ETA. NO
  push notifications, NO transactional SMS, NO email receipts (all
  DEFERRED with explicit trigger conditions).

### ADR-040 — Rider Mobile App & Delivery Dashboard Contract

Formally accepts the as-built rider-facing + delivery dashboard
surface:

- **Rider surface:** `rider` role + `/staff/login` (ADR-017) +
  `isRiderOnly` scope check (ADR-030 §3). 4 rider-facing routes
  under `/api/v1/riders/*`: assignments list, roster, assign,
  status transition. NO native rider mobile app — riders use admin
  web on mobile browser.
- **Rider identity + dispatch:** ADR-030 — 1:1 `user_id` + 1:1
  `branch_id`; manual dispatch via
  `POST /api/v1/riders/deliveries/:id/assign` with 8 invariants.
  Auto-dispatch DEFERRED.
- **Delivery lifecycle + POD:** ADR-031 — 6-state machine
  (assigned→picked-up→delivered, with failed + cancelled terminals);
  POD mandatory for `delivered` via trigger + service + UI.
- **Rider location + GPS ingest:** ADR-008/032 — `rider_locations`
  ephemeral table with 24h TTL purge; GPS ingest endpoint
  `POST /api/v1/riders/deliveries/:id/location` with
  active-delivery-only enforcement. 3 indexes for latest-ping +
  per-delivery list + TTL purge range scan.
- **Admin delivery dashboard:** `AdminDelivery.tsx` (550 lines) +
  8 sub-components totaling ~3,500 lines:
  - `DeliveryCards.tsx` — card grid view of active deliveries
  - `DeliveryDrawer.tsx` — slide-out detail drawer
  - `DeliveryFilters.tsx` — filter bar (status, branch, rider, date)
  - `DeliveryInsights.tsx` — aggregate insights panel
  - `DeliveryKPIs.tsx` — KPI tiles (total, active, completed, failed)
  - `DeliverySidePanels.tsx` — right-side context panel
  - `DeliveryTimeline.tsx` — per-delivery event timeline
  - `DispatchQueue.tsx` — queue of unassigned deliveries
- **10 admin delivery routes:** `backend/api/src/modules/admin/delivery-rider.ts`
  mounted at `/api/v1/admin/delivery-rider/*` — list, detail, assign,
  status, POD, location ingest, location list, rider roster, KPIs,
  insights.
- **Aggregate KPIs:** DeliveryKPIs + DeliveryInsights components
  backed by `delivery-kpi-service.ts` — total/active/completed/failed
  counts, average delivery time, late count, on-time %.
- **DEFERRED from Phase 9 ADR-032 §8-12:** per-rider KPIs +
  `rider_daily_summaries` table, rider mobile app (turn-by-turn,
  in-app call, offline-tolerant), customer-facing live map, push
  notifications, audible alarms, live rider map (admin) — all with
  explicit trigger conditions in ADR-040 §8.

### ADR-041 — Staff App & Support Panel Contract

Formally accepts the as-built staff-facing + support panel surface:

- **Admin shell:** `AdminShell.tsx` with permission-gated sidebar +
  topbar + role-appropriate home page routing.
- **37 admin pages:** `apps/website/client/src/pages/admin/*.tsx` —
  full coverage of all 10 ERP modules: dashboard, branches, cashier,
  CRM, delivery, finance, floor, HR, inventory, kitchen, loyalty,
  marketing, menu, orders, POS, purchasing, reports, reservations,
  settings, supplier operations, WhatsApp.
- **5 ops pages:** `apps/website/client/src/pages/ops/` — OpsShell
  (89 lines) + OpsDashboard (193 lines) + OpsDispatch (162 lines)
  + OpsKitchen (143 lines) + OpsOrders (218 lines). Tablet-optimized
  for branch-manager floor operations.
- **32 admin router modules:** `backend/api/src/modules/admin/*.ts`
  totaling 350+ routes. Largest modules: `hr.ts` (48 routes),
  `finance.ts` (35 routes), `opening-governance.ts` (33 routes),
  `opening-operations.ts` (25 routes), `marketing.ts` (23 routes),
  `purchasing.ts` (22 routes).
- **Staff role catalog:** ADR-019 RBAC with 8 canonical roles
  (`platform_super_admin`, `organization_owner`, `finance`, `hr`,
  `auditor`, `branch_manager`, `kitchen_manager`, `support`) +
  4 legacy roles (`super-admin`, `branch-manager`, `kitchen`,
  `cashier`, `rider`, `customer-support`). Identity 01 migration
  (`20260807100000`) seeds canonical roles with permission copy
  from legacy codes.
- **Kitchen Display System:** ADR-027/028/029 — `AdminKitchenDashboard.tsx`
  4-column board, 8s polling, 6-state ticket lifecycle, KOT snapshot,
  atomic stock consume via `kitchen_ticket_set_preparing_atomic`
  SECURITY DEFINER RPC, branch isolation via RLS.
- **POS cashier workflow:** ADR-023/024/025/026 — `AdminPos.tsx`
  + `AdminCashierHome.tsx` with cash-only contract, 4 payment
  methods, branch sync + offline-safe via Idempotency-Key.
- **Support panel (de facto):** `AdminCrm.tsx` (306 lines) + 8 CRM
  routes in `customers.ts` + `AdminWhatsApp.tsx` + 11 WhatsApp
  routes in `whatsapp.ts` (ADR-003/004). `support` role seeded
  (canonical) with read access to customer + order + payment data
  across assigned branches.
- **Audit log:** `audit_log` table (ADR-012) + `AdminAuditLog`
  page + 5 routes in `audit.ts`. All staff actions recorded with
  actor `user_id` + action + target + before/after JSONB.
- **PII anonymization:** 24-month WhatsApp conversation PII
  anonymization job (Phase 2.2 PR #221).
- **DEFERRED:** mobile-optimized staff UI, PWA-installable admin,
  branch-manager mobile checklist, kitchen handheld view (per-item
  prep ticks), customer 360 unified view, ticketing system, refund
  initiation workflow (depends on ADR-038 §8 `refunds` table),
  auto-routing WhatsApp to support agent — all with explicit
  trigger conditions in ADR-041 §8.
